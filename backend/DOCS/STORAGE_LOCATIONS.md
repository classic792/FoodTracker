# Storage Location API

All endpoints require the Bearer token or staff session cookie established by `POST /api/auth/login`; browser clients using cookies must use `credentials: "include"`. See [AUTH.md](./AUTH.md) for authentication, Postman setup, and origin configuration. Responses have `Cache-Control: no-store`.

## Endpoints

| Method and path | Accepted input | Success |
| --- | --- | --- |
| `POST /api/storage-locations` | Required `name`; optional `description` | `201`, location object |
| `GET /api/storage-locations` | No query parameters | `200`, `{ items: [...] }` |
| `GET /api/storage-locations/:id` | UUID path parameter | `200`, location object |
| `PATCH /api/storage-locations/:id` | UUID; body containing `name` and/or `description` | `200`, updated location object |
| `DELETE /api/storage-locations/:id` | UUID path parameter; no body | `204`, empty body |

Single-location objects contain exactly `id`, `name`, `description`, `createdAt`, and `updatedAt`, without a wrapper or embedded batches. Dates are ISO-8601 strings; description may be `null`. IDs are generated by the service with `crypto.randomUUID()`.

The list returns all locations without pagination or filtering. Each item contains exactly `id`, `name`, and `description`, suitable for selectors binding an ID to a display name. Ordering is name ascending, then ID ascending, deterministic for unchanged data. An empty database returns `{ "items": [] }`. Query parameters, including pagination parameters, are rejected with `400 VALIDATION_ERROR`.

## Validation and updates

- Names are trimmed and must contain 1–100 characters. Creation requires a name; PATCH validates it when supplied. Null, blank, and non-string names are rejected.
- Name uniqueness follows the existing PostgreSQL constraint: `Shelf A` and `shelf a` are distinct names. Surrounding spaces are removed before storage. Duplicate creates and renames, including concurrent attempts, return `409 DUPLICATE_LOCATION_NAME`.
- Description accepts a string or `null`. Strings are trimmed; blank strings become `null`. Omission on creation stores `null`; omission on PATCH preserves the current description. Explicit `null` clears it.
- POST and PATCH require JSON objects and reject unknown fields, including caller-supplied IDs or timestamps. PATCH requires at least one of name or description, preserves omitted fields, and explicitly updates `updatedAt` while preserving ID and creation time.
- GET-by-ID, PATCH, and DELETE validate the path ID using Joi `.uuid()` before service calls. PATCH validates the ID before its body. Malformed IDs return `400 INVALID_ID`; valid UUIDs with no matching location return `404 LOCATION_NOT_FOUND` for otherwise valid requests.

## Errors and deletion safety

Errors use the shared envelope:

```json
{
  "error": {
    "code": "DUPLICATE_LOCATION_NAME",
    "message": "A storage location with this name already exists."
  }
}
```

| HTTP status | Code | Message / cause |
| --- | --- | --- |
| `400` | `INVALID_ID` | `Location id must be a valid UUID.` |
| `400` | `VALIDATION_ERROR` | Field-specific message; unknown fields: `Unknown fields are not allowed.`; empty PATCH: `Provide at least one of name or description.` |
| `400` | `INVALID_JSON` | `Request body must be valid JSON.` |
| `401` | `UNAUTHORIZED` | `Authentication required.` |
| `403` | `ORIGIN_FORBIDDEN` | `Request origin is not allowed.` |
| `404` | `LOCATION_NOT_FOUND` | `Storage location not found.` |
| `404` | `NOT_FOUND` | `Endpoint not found.` for unsupported URLs |
| `409` | `DUPLICATE_LOCATION_NAME` | `A storage location with this name already exists.` |
| `409` | `LOCATION_IN_USE` | `This location has batches on record and cannot be deleted.` |
| `413` | `PAYLOAD_TOO_LARGE` | `Request body is too large.` |
| `500` | `INTERNAL_ERROR` | `An unexpected error occurred.` |

Missing, invalid, expired, or inactive-account sessions are rejected before location controllers/services run. Existing global origin and JSON parsing middleware still run before authentication.

Deletion is a hard delete. Any referencing batch, including a zero-quantity batch, prevents deletion through the existing PostgreSQL `onDelete: Restrict` foreign key. The service translates Prisma `P2003` into `409 LOCATION_IN_USE` without batch-count prechecks. Missing records on update/delete translate `P2025` to `404 LOCATION_NOT_FOUND`. Unexpected database errors are not exposed.

## Manual request examples (not executed)

First log in using a development staff account; reuse its cookie for each request and send `Content-Type: application/json` for JSON bodies. IDs and timestamps below are illustrative; substitute the returned ID in subsequent requests.

Create: `POST /api/storage-locations`

```json
{ "name": "Shelf A", "description": "Dry goods" }
```

Expected `201`:

```json
{
  "id": "27e86422-daf3-453a-94be-d6c26cb3cb84",
  "name": "Shelf A",
  "description": "Dry goods",
  "createdAt": "2026-09-25T10:00:00.000Z",
  "updatedAt": "2026-09-25T10:00:00.000Z"
}
```

Repeating the create returns `409` with the duplicate-name envelope above. Creating `{ "name": "Chiller" }` returns `201` with description `null`.

List: `GET /api/storage-locations`, no body. Assuming these are the only locations, expected `200` (Chiller ID illustrative):

```json
{
  "items": [
    {
      "id": "520c2fa7-3daa-4e82-a599-6a02c8f45a63",
      "name": "Chiller",
      "description": null
    },
    {
      "id": "27e86422-daf3-453a-94be-d6c26cb3cb84",
      "name": "Shelf A",
      "description": "Dry goods"
    }
  ]
}
```

Fetch: `GET /api/storage-locations/27e86422-daf3-453a-94be-d6c26cb3cb84`, no body. Expected `200` with the full Shelf A object, including timestamps.

Rename: `PATCH /api/storage-locations/27e86422-daf3-453a-94be-d6c26cb3cb84`

```json
{ "name": "Store Room" }
```

Expected `200`:

```json
{
  "id": "27e86422-daf3-453a-94be-d6c26cb3cb84",
  "name": "Store Room",
  "description": "Dry goods",
  "createdAt": "2026-09-25T10:00:00.000Z",
  "updatedAt": "2026-09-25T10:01:00.000Z"
}
```

On the same PATCH URL, `{ "description": null }` returns `200` with description `null`, the same name/ID/creation time, and a new `updatedAt`. `{ "description": "   " }` also clears it. `{ "name": "Chiller" }` returns `409 DUPLICATE_LOCATION_NAME` while leaving the location unchanged. `{}` returns `400 VALIDATION_ERROR`.

Invalid ID: `GET /api/storage-locations/not-a-uuid` returns `400`:

```json
{ "error": { "code": "INVALID_ID", "message": "Location id must be a valid UUID." } }
```

An otherwise valid GET, PATCH, or DELETE using a UUID absent from the database returns `404`:

```json
{ "error": { "code": "LOCATION_NOT_FOUND", "message": "Storage location not found." } }
```

Delete: `DELETE /api/storage-locations/27e86422-daf3-453a-94be-d6c26cb3cb84`, no body. Expected `204` with no body if unreferenced; repeating a successful deletion returns `404 LOCATION_NOT_FOUND`. If any batch references the location, expect `409` and preservation of the location:

```json
{ "error": { "code": "LOCATION_IN_USE", "message": "This location has batches on record and cannot be deleted." } }
```

## Manual verification checklist

- Active sessions can use all five endpoints; missing, invalid, expired, and inactive-account sessions return `401` on otherwise valid requests. Verify `Cache-Control: no-store`.
- Missing, null, blank, overlength (101 characters), wrong-type, and unknown fields return `400`. Verify 100-character names work, whitespace is trimmed, and case is retained.
- Duplicate creation and rename return `409`, including concurrent attempts; case variants remain distinct. Renaming to the current name succeeds.
- Name-only and description-only PATCH requests preserve omitted fields. Null/blank descriptions clear the value. IDs and creation times remain unchanged; update times advance. Empty and missing bodies fail.
- Malformed UUIDs return `400 INVALID_ID` for GET, PATCH, and DELETE; well-formed nonexistent IDs return `404 LOCATION_NOT_FOUND` with valid input. Invalid PATCH IDs are checked before body validation.
- Lists include all locations, only selector fields, and stable name/ID ordering. Empty lists return `{ "items": [] }`; unsupported query parameters return `400`.
- Unreferenced deletion succeeds with an empty `204`; referenced locations remain after `409`, including references from zero-quantity batches.
- Origin rejection, malformed JSON, and oversized bodies retain the shared errors above.

Implementation verification is limited to JavaScript syntax checks and diff review. No endpoint tests, test files, seeds, fixtures, schema changes, migrations, or database writes were performed for this feature. Batch, Product, and StockMovement endpoints are unchanged.
